# demo-canvas

视频创作画布交互原型，保留文本、图片、视频节点与本地素材。本轮按《功能与交互改版指引.md》改进视频面板。

## 在线访问

- 演示：https://sunnygirl-0106.github.io/demo-canvas/
- 已连接素材的工作流：https://sunnygirl-0106.github.io/demo-canvas/?scene=1
- 公开源码：https://github.com/sunnygirl-0106/demo-canvas

推送到 `main` 后，GitHub Actions 自动运行测试、构建并发布到 GitHub Pages。

## 启动与检查

```bash
npm install
npm run dev
npm test
npm run build
```

默认地址为 `http://localhost:5273`，端口占用时以终端输出为准。
默认画布竖着排成两列，供走查用：11 段长短不一的视频、8 张参考图、2 个文本，外加视频 / 图片 / 文本各一个空态；
`?scene=1` 打开已连接素材的工作流，`?scene=empty` 打开空画布。
短片都是从 `public/media` 里原有的四段视频裁出来的（`clip-*.mp4`），不是新生成的素材。
时长有意铺在几条规则的两边，缩略图左下角直接标出来：1.5s（谁都编辑不了，节点上的入口就是灰的）、
2s / 3s（只有 2.0 系列能编辑）、4.2s 起（2.5 也能编辑）、5.1s、6s、8s、10.1s。
11 段还越过了 Seedance 2.5 的 10 段视频配额，合计时长也够撞 2.0 的 15 秒输入上限。

## 视频操作

- 视频节点上方有并列的「编辑视频」「延长视频」入口。首次操作创建下游任务节点，保留源视频；再次进入恢复同一节点的草稿。
- 文生视频、首尾帧、参考图 / 全能参考、编辑、延长分别保存素材角色、文字、模型和参数。切换模式不删除画布资产或连接；当前不参与的连接弱化。
- 素材不够被动切走时，草稿存回它自己的模式，不跟着带进新模式：断开源视频再接上新视频，回到编辑仍是原来的文字与参数，只清除标记 —— 标的是上一段画面上的东西，换了片子就没有意义了。被挤走的草稿也不会被记上那个不支持它的模型。
- 首尾帧固定 72×60 px；可交换、替换、移除。移除首帧不会自动提升尾帧。点击已有素材预览，点击空槽添加，通过「⋯」替换或移除。
- 素材悬浮联动画布连线，停留后显示独立浮层。图片完整大图预览，视频原生播放器支持进度和声音；Esc 关闭并恢复焦点。
- `@` 选择本次实际使用的已连接资产，引用绑定稳定资产 ID，不代表顺序。引用标签和句首那枚源素材是同一枚：小缩略图 + 名字，悬浮放大，图片和视频一视同仁 —— 名字是四字母随机 id，光有名字认不出是哪一段。提示词这一块按最高的那一档（有工具行的编辑模式）定死，换 Tab 不会整块往上蹿一截；没有工具行的模式把多出来的高度给可编辑区，不是留一条空带子。
- Tab 行只摆当前型号做得了的那几件事：型号没有的能力（可灵的编辑、Wan 的全能参考）不出现，灰掉的 Tab 一律只意味着「这件事它会做，但画布上的素材还不够」—— 两句话不挤在同一个位置上。「这个型号做不了我要的事」由模型列表那一头说，编辑 / 延长另有视频节点上的入口，从那儿进来会自动换成接得住的型号。
- 模式入口与生成校验共用同一条素材规则，不会出现入口全部置灰却仍能提交的任务。
- 参考分成互斥的两个 Tab：只收参考图的型号（Wan 2.2、Seedance 1.5）拿「参考图」，收图 / 视频 / 音频多模态的（Seedance 2.0 与 2.5、可灵 O1）拿「全能参考」。一个型号只会有其中一个，另一个根本不摆在 Tab 行上 —— 用的还是 `genModes` 那条现成规则，没有新机制。只收图的型号视频配额是 0，连着的视频缩略图置灰并说「XX不使用视频素材」。
- 选得了、但换过去会变样的型号，在做选择之前就说：模型那一行悬浮出「此模式会忽略已连接的视频节点」—— 和换过去之后那个 Tab 上挂的是同一句话（`modelNote` 复用 `tabNote`），落在哪个 Tab 也和 `setModel` 共用一条判断（`modeAfterModel`），说的和做的不会是两回事。说明贴在那一行的侧边，不压在正上方 —— 一行挨一行的列表里，盖住的恰好是用户正在比较的上一行。
- 模型列表和模式入口是同一条规则的两头，都由 `modelBlockedReason` 一个入口给理由：型号做不了当前这个模式（编辑时的可灵、Wan 等）、接不住已经标好的范围（不响应范围的 2.0 系列）、或者在当前连接下一个模式都进不去（只做文生视频的型号连了素材、只做图生视频的型号空画布），三种情况一律置灰并在那一行悬浮说明，不让用户选进一个自己改不动的死角。
- 所有置灰的控件都在悬浮或键盘聚焦时弹出气泡说明原因（Tab、模型、标记入口、弹窗里的撤销 / 清除 / 添加、视频节点上的编辑 / 延长入口共用一个 `useTip`）。置灰一律用 `aria-disabled` 而不是 `disabled`：后者不发鼠标事件也拿不到焦点，说明就没人看得到。
- 源视频时长不合规不再是「进去之后的黄字」：连着的视频没有一段落在区间内时，编辑 / 延长的 Tab 直接灰掉并说出区间，还会指出换哪个型号可以（2.5 编辑要 4 秒起，2.0 只要 2 秒）。视频节点上的入口同理，没有任何型号接得住这段时长时就灰掉。接得住但当前型号不行时，从入口进去会自动换成接得住的型号，而不是把人丢在一个灰掉的 Tab 上。
- 某个模式用不上的素材不在面板里占位：进不去的 Tab 悬浮说原因，进得去但会忽略素材的 Tab 悬浮说一句「此模式会忽略已连接的视频节点」，连接与缩略图都不动。
- 局部编辑是**标记式**的，只有编辑有：提示词工具行左侧的「标记要改的地方」打开弹窗，在画面上框选或涂抹要改的那一块，可选再在轨道上拉一段时间。一次弹窗产出一组，组里能圈多处、最多带一段时间；添加之后成为句子里的一枚标签：「把 [视频] 中 [📹 00:01–00:03] 里的 [⬚ 00:01] 的 …」，读下来就是这次任务的全部意思。时间段那一枚是「片段图标 + 起止时间」一行读完 —— 「这是视频里的一截」由图标说，不再写「时间段」三个字，也不在标签里再画一条细轨。延长没有这一层 —— 永远拿整条原片去续写，往哪头接由方向决定。
- 标签悬浮出那一帧的预览（带标记与选区条），点开逐处列出，× 整组删除 —— 一组是一次会话的产物，中间不拆。面板上不再有「改整条 / 改这一段」分段器：有没有作用范围由标记自己带着，没标记就是改整条。
- 弹窗里：按下画面即暂停到那一整秒并开始标记，框可拖可缩、太小的当误触丢掉；画笔同一秒的多笔算一处；轨道按整数秒选取，点击新建、拖两端调整、拖选区平移，端点与选区主体支持方向键；标记掉在所选时间段外只琥珀色提醒一句，不拦提交。工具行右侧只留一个「撤回上一步」，清空整次标记走标题栏的「清除全部」—— 同一件事不摆两个按钮，也不留一把会被误读成「擦掉笔迹」的橡皮擦；两者在空草稿时各自置灰并说出原因；带着草稿关闭先问「放弃这组标记？」。
- 每标一处就自动截下那一帧（标记画在图上），作为**标记参考图**挂在源视频右边的参考素材栏里，一秒一张、同一秒的几处画在同一张上，和别的参考素材长得一样 —— 图上画着的红框自己就说明了它是怎么来的，不再另加描边或时间角标。它完全由句子里还留着的标记决定：删掉一枚标签，右边那张图跟着消失。
- 更换源资产或其媒体文件静默清除标记：句子里的标签当场消失、入口旁的计数回到「未标记」，这本身就是反馈，不另弹横幅。
- 延长默认向后，向前 / 向后分别表示「新增 → 原视频」「原视频 → 新增」，提示词前缀常驻显示当前方向与新增时长。新增时长在参数浮层里设置，不以 30 秒减原片时长计算。
- 视频时长要求按任务类型分，待编辑视频和辅助参考视频共用同一条：2.5 的编辑任务两者都是 4–30 秒（2.0 系列 2–30 秒），参考生成新视频与延长一律 2–30 秒。换过去会让手上的参考视频不合规的型号，在模型列表里就灰掉并说出区间。
- 视频输入时长按本次有效输入计算，每段视频都按整条原片计入合计。参考视频同样要能读出时长。
- 模型与参数为独立入口；模型清单与平台一致，不支持当前模式或会让标记失效的型号显示原因。参数浮层即时保存清晰度、时长、比例和声音，编辑时长随原片，Seedance 2.5 首尾帧比例随首帧，编辑与延长比例随原片；可灵与 Wan 没有声音开关。提交记录与界面显示的参数一致：不锁定比例的型号照手选值提交，没有声音开关的型号不夹带声音。换到不响应范围的型号时标记留着不被抹掉 —— 手画的东西比一个开关贵，那些型号在列表里本来就是灰的，真要放大范围由「移除标记，改为整条」显式解除。
- 画布保留节点拖动、连线、复制粘贴、撤销重做、文件上传和外部文件拖入。

## 演示范围

视频生成按钮只创建、完成并记录演示任务。可下载 JSON 查看源视频、有效资产 ID、引用、标记组（逐处的归一化坐标、笔迹与秒数）、标记参考图截自第几秒、时间范围、方向、输出含义和参数快照。不调用真实模型，不扣费，不裁切编码，不生成或冒充 AI 编辑结果。

整段编辑目标为整条视频；延长目标为新增片段。本轮不自动拼回源视频，也不承诺逐帧精准修改。

状态保存在内存，刷新或切换示例场景会重置。图片与文本仍使用原有模拟生成功能。所有默认媒体位于 `public/media`，图片模拟生成仍使用在线图片。

## 验证重点

`src/store/generator.test.ts` 覆盖草稿恢复、换源、引用清理、模型兼容、任务快照，以及断线换源、模型来回切换这类连续操作。`src/generator/marks.test.ts` 覆盖标记本身的规则：误触的小框、画笔外接框与采点阈值、一组标记怎么读、作用范围怎么推出来、越界与失效的判断、时间段的取法。画布撤销与真实媒体元数据测试继续保留。

主目录：`src/canvas`（画布）、`src/nodes`（节点与媒体）、`src/generator`（面板、标记弹窗、预览、参数与任务逻辑）、`src/store`（状态）、`src/demo`（本地样例）。
