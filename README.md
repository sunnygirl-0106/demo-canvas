# demo-canvas

视频创作画布交互原型，保留文本、图片、视频节点与本地素材。本轮按《功能与交互改版指引.md》改进视频面板。

## 在线访问

- 演示：https://sunnygirl-0106.github.io/demo-canvas/
- 已连接素材的工作流：https://sunnygirl-0106.github.io/demo-canvas/?scene=1
- 公开源码：https://github.com/sunnygirl-0106/demo-canvas

推送到 `main` 后，GitHub Actions 自动运行测试、构建并发布到 GitHub Pages。

## 启动与检查

```bash
npm install
npm run dev
npm test
npm run build
```

默认地址为 `http://localhost:5273`，端口占用时以终端输出为准。
默认画布竖着排成两列，供走查用：11 段长短不一的视频、8 张参考图、2 个文本，外加视频 / 图片 / 文本各一个空态；
`?scene=1` 打开已连接素材的工作流，`?scene=empty` 打开空画布。
短片都是从 `public/media` 里原有的四段视频裁出来的（`clip-*.mp4`），不是新生成的素材。
时长有意铺在几条规则的两边，缩略图左下角直接标出来：1.5s（谁都编辑不了，节点上的入口就是灰的）、
2s / 3s（只有 2.0 系列能编辑）、4.2s 起（2.5 也能编辑）、5.1s、6s、8s、10.1s。
11 段还越过了 Seedance 2.5 的 10 段视频配额，合计时长也够撞 2.0 的 15 秒输入上限。

## 视频操作

- 视频节点上方浮出「局部修改」「延长视频」「版本记录 N」「下载」四个入口。四件事不等重：「局部修改」是这排里唯一会把人带进另一种状态的那一件，所以它自己是一枚实心块、图标着青色，后面一条竖线把它和另外三件顺手的事分开 —— 每两个之间都插一条竖线，那条线也就什么都没说了。版本数是这枚入口带着的一个数，给它一块自己的底，不跟名字连读成「版本记录1」。首次操作创建下游任务节点，保留源视频；再次进入长出新的操作节点（上一个还没出结果时才复用它）。
- 从入口长出来的那个节点是**专注态**：比普通视频节点宽了一倍（420 vs 200），因为它不是画布上的又一枚缩略图，而是这段时间里用户唯一在看的那块屏 —— 要在上面看清画面、圈准一块地方、再拖一段时间。200px 里圈一张脸，手一抖就是 32px 的误差；420px 上同样的手抖只有 15px。它的节点体也不套普通节点那层渐变底，而是一块纯黑的屏加一圈青边，落地时轻轻弹一下。出片那一刻专注态结束，宽度缩回普通节点 —— 产出的视频和画布上别的视频节点长得一样。
- 专注态的标题栏右边写一句「编辑中 / 延长中」，说的是「正在做哪件事」。它不镶框 —— 一圈描边是给可点的东西用的，一句状态框起来就像颗按钮；浅一档的青（`--teal-pale`）说明「这会儿有事正在发生」。图标自己在写字：一支青色的笔从左往右歪歪扭扭地走，底下那道半透明的白痕用 `stroke-dashoffset` 跟着笔尖一点点露出来 —— 看着才是「它写出来的」，而不是「它在一条画好的线上滑」；写到最右边收笔，「编 辑 中」三个字依次轻轻弹一下（错开 70ms 起跳，读起来才是一个一个写出来的），然后隐去、退回左边重写。笔身和墨是两个颜色、笔尖是同一支白但实一档：同色摆在一起，笔杆和它刚写下的那道痕会糊成一团。延长态另一套 —— 它那枚加号在原地呼吸，没有「写到头」那个时刻可对，字也就不拆。一句静止的字说的是「现在是编辑态」，一枚在动的图标说的才是「正在编辑」。左边那枚图标不跟着换，始终是视频节点自己的图标，一眼读到的还是「这是个视频节点」，颜色也跟着中性灰走 —— 一行里两处着青，反倒不知道该看哪一处。不改了就直接删掉这个还没出片的节点（Delete，⌘Z 接回来），标题栏上不再另留一枚 ×。徽章从画面右上角搬到了标题栏 —— 画面上就只剩画面和画在它上面的标记，一个字都不压着。连出来的那条线也就地说出它长出来的是什么事（「局部重绘」「延长续写」）：线两头的名字都是「视频节点」，不说这一句，那个节点为什么在那儿就只能靠猜。
- 「版本记录」是挂在节点侧边的一枚气泡，不是居中弹窗：它说的是**这一段视频**的事，尖角就指着那个节点。竖向不居中，而是**顶边对顶边**：气泡从节点的上沿起，一路往下长 —— 列表页越往下越长（版本一多就是两排），居中摆会把上半屏空掉、再把下半屏顶出视窗；顶边对齐之后，一排还是两排，起点都在同一个地方，尖角也始终停在节点中线上。「按气泡自己高度偏几分之几」那种写法试过，不成：气泡一高，顶边就被顶到节点上方去了，看着还是绕着中线在摆。右边放不下自动翻到左边，尖角跟着换边，指的还是同一个节点。色板不照搬稿子：稿子那一套底色带绿味（#111817 / #7d8e89），摆进这个画布就成了另一支色 —— 一块浮层比它底下的节点更绿，读到的第一件事是「它跟别处不一样」。所以只承接稿子的**明度关系**（浮层底 → 卡片底 → 选中档各抬一级，正文 → 注脚 → 描边各降一级），色相一律交给中性灰那套 token；青色只剩主操作那一行字，它本来就该是全局强调色。整块界面的大小由样式里一个 `--vp-k` 说了算：稿子上的每个数原样留着、统一乘它，要再大 / 再小一档只改这一个数，稿子定下的比例关系一个都不走样。气泡里分两页 —— 先是一屏卡片（这个节点做出过哪几幅画面），点一张才进那一版的细节，返回处写的是上一页的名字「版本记录」而不是一个光秃秃的「返回」。分页而不是「列表下面接一块详情」，是因为提示词是整段的话：一段话垫在一屏卡片底下，卡片被挤到看不全，话也读不完整。细节页左边是 200×340 的一块竖版画面（竖片正好，横片只取中间那一条），右边从上到下是版本号与分类、出身与时间、整段提示词，参数沉到底边压在一条细线下 —— 它是查证用的，不该横在提示词和画面之间。主操作也不再是一枚实心青块，而是右上角一行带下划线的字（「在画布中查看」/「添加到画布」）：这一页真正的主角是那幅画面和那段话，一块高饱和的色块摆在角上，眼睛就先落在按钮上了。
- 「版本记录」收的是这个节点承载过的画面，加上直接从它派生出去的那一层，分成「生成 / 编辑 / 延长」三档。分的是画面和**这个节点**的关系，不是名字：节点自己交出来的一律在「生成」里 —— 不管做出它的是文生视频、参考生成，还是从上游点「局部修改」进来的那一次任务，所以叫「局部修改视频：视频节点1」的节点打开历史，默认亮起的仍是「生成」。「编辑」「延长」留给从它派生出去的那一层，是哪一档由那次任务的模式说。改提示词在原地再生成一次，只是往自己的「生成」里再添一版，先前那一版还在，下游节点已经生成过的那一版记的也还是它当时用的画面。
- 画布上的视频节点**按素材本来的比例摆**：竖片是竖的（200×356），横片是横的（356×200），画面填满、两边都不留黑。摆进一块固定的横板里，一段竖片两边各留一条黑，等于一个节点有一半在说「这儿没东西」。比例量自封面（`useAspect`），量出来就把节点摆成那个形状（`canvas.shape`，不进撤销栈 —— 这是量出来的，不是用户改的）；还没量出来先按 9:16 兜着。「多大」不再由宽度一个数说了算，而是**面积恒定**：宽 = √(面积 × 比例)、高 = 宽 ÷ 比例，所以 9:16 摆出 200×356、16:9 摆出 356×200、1:1 摆出 267×267，三种朝向占的地方一样大，和 320×200 的图片节点也在同一个量级上。演示画布的视频区因此按「最宽的那种 × 最高的那种」留格子（400×430，一行三个），横竖不一的边缘参差是「各按各的比例」本来就会有的样子，不去硬凑齐；图片和文本仍是固定 320×200 的两列。专注态那块编辑屏同理：它也按素材本来的比例摊开（量不到退回 9:16），横片摊成横片、竖片摊成竖片 ——这块屏存在的意义就是「在上面圈准一块地方」，套死一个 16:9，一段竖片进来能圈的只剩当中窄窄一条。宽度也因此从 580 收到 420：一段 9:16 的竖屏在 580 宽上高到 1031px，一屏放不下；而竖屏里真正能圈的面积反倒比原来大 —— 原先那块 580×326 的板子，竖片摆进去只占当中 183px 宽。落在 420 而不是更窄，是因为画面下面那截轴压矮了三分之一（124 vs 184）：省出来的高度全给了画面，整个节点没有长高，画面却从 676 长到 738。
- 文生视频、首尾帧、参考图 / 全能参考、编辑、延长分别保存素材角色、文字、模型和参数。切换模式不删除画布资产或连接；当前不参与的连接弱化。
- 素材不够被动切走时，草稿存回它自己的模式，不跟着带进新模式：断开源视频再接上新视频，回到编辑仍是原来的文字与参数，只清除标记 —— 标的是上一段画面上的东西，换了片子就没有意义了。被挤走的草稿也不会被记上那个不支持它的模型。
- 首尾帧固定 72×60 px；可交换、替换、移除。移除首帧不会自动提升尾帧。点击已有素材预览，点击空槽添加，通过「⋯」替换或移除。
- 素材悬浮联动画布连线，停留后显示独立浮层。图片完整大图预览，视频原生播放器支持进度和声音；Esc 关闭并恢复焦点。
- `@` 选择本次实际使用的已连接资产，引用绑定稳定资产 ID，不代表顺序。引用标签和句首那枚源素材是同一枚：小缩略图 + 名字，悬浮放大，图片和视频一视同仁 —— 名字是「视频节点3」这种按类型的编号，认得出是第几段，但认不出画面，所以缩略图一直摆在名字旁边。提示词这一块按最高的那一档（有工具行的编辑模式）定死，换 Tab 不会整块往上蹿一截；没有工具行的模式把多出来的高度给可编辑区，不是留一条空带子。
- Tab 行只有一枚青色滑点标当前模式，没有下划线：当前在哪一档由这枚点说，一条横线只是又说了一遍。Tab 行只摆当前型号做得了的那几件事：型号没有的能力（可灵的编辑、Wan 的全能参考）不出现，灰掉的 Tab 一律只意味着「这件事它会做，但画布上的素材还不够」—— 两句话不挤在同一个位置上。「这个型号做不了我要的事」由模型列表那一头说，编辑 / 延长另有视频节点上的入口，从那儿进来会自动换成接得住的型号。
- 模式入口与生成校验共用同一条素材规则，不会出现入口全部置灰却仍能提交的任务。
- 参考分成互斥的两个 Tab：只收参考图的型号（Wan 2.2、Seedance 1.5）拿「参考图」，收图 / 视频 / 音频多模态的（Seedance 2.0 与 2.5、可灵 O1）拿「全能参考」。一个型号只会有其中一个，另一个根本不摆在 Tab 行上 —— 用的还是 `genModes` 那条现成规则，没有新机制。只收图的型号视频配额是 0，连着的视频缩略图置灰并说「XX 不支持视频输入」。
- 选得了、但换过去会变样的型号，在做选择之前就说：模型那一行悬浮出「视频不参与本次生成」—— 和换过去之后那个 Tab 上挂的是同一句话（`modelNote` 复用 `tabNote`），落在哪个 Tab 也和 `setModel` 共用一条判断（`modeAfterModel`），说的和做的不会是两回事。说明贴在那一行的侧边，不压在正上方 —— 一行挨一行的列表里，盖住的恰好是用户正在比较的上一行。
- 模型列表和模式入口是同一条规则的两头，都由 `modelBlockedReason` 一个入口给理由：型号做不了当前这个模式（编辑时的可灵、Wan 等）、接不住已经标好的范围（不响应范围的 2.0 系列）、或者在当前连接下一个模式都进不去（只做文生视频的型号连了素材、只做图生视频的型号空画布），三种情况一律置灰并在那一行悬浮说明，不让用户选进一个自己改不动的死角。
- 所有置灰的控件都在悬浮或键盘聚焦时弹出气泡说明原因（Tab、模型、节点上编辑台的撤回 / 清除 / 片段开关、视频节点上的编辑 / 延长入口共用一个 `useTip`）。置灰一律用 `aria-disabled` 而不是 `disabled`：后者不发鼠标事件也拿不到焦点，说明就没人看得到。
- 源视频时长不合规不再是「进去之后的黄字」：连着的视频没有一段落在区间内时，编辑 / 延长的 Tab 直接灰掉并说出区间，还会指出换哪个型号可以（2.5 编辑要 4 秒起，2.0 只要 2 秒）。视频节点上的入口同理，没有任何型号接得住这段时长时就灰掉。接得住但当前型号不行时，从入口进去会自动换成接得住的型号，而不是把人丢在一个灰掉的 Tab 上。
- 某个模式用不上的素材不在面板里占位：进不去的 Tab 悬浮说原因，进得去但有素材用不上的 Tab 悬浮说一句「视频不参与本次生成」，连接与缩略图都不动。
- 局部编辑是**标记式**的，只有编辑有：入口不在面板里，而是画面本身 —— 点视频节点上的「局部修改」连出一个专注态节点，原片就摆在这个节点上，在画面里框选或涂抹要改的那一块，可选再在画面下面的轨道上拉一段时间。它没有「打开 / 关闭」这个回合，所以也没有提交和取消：圈一个框当场就进句子 ——「把 [视频] 中 [📹 00:01–00:03] 里的 [⬚ 00:01] 的 …」，读下来就是这次任务的全部意思。时间段那一枚是「片段图标 + 起止时间」一行读完 —— 「这是视频里的一截」由图标说，不再写「时间段」三个字，也不在标签里再画一条细轨。延长没有这一层 —— 永远拿整条原片去续写，往哪头接由方向决定。
- 标签悬浮出那一帧的预览（带标记与选区条），点开逐处列出，× 整组删除 —— 一组是一次会话的产物，中间不拆。句子是唯一真相：退格删掉一枚标签，节点上那个框当场跟着消失。面板上不再有「改整条 / 改这一段」分段器：有没有作用范围由标记自己带着，没标记就是改整条。
- 节点上那块编辑台：按下画面即暂停到那一整秒并开始标记，框可拖可缩、太小的当误触丢掉；画笔同一秒的多笔算一处；轨道按整数秒选取，点击新建、拖两端调整、拖选区平移，端点与选区主体支持方向键。正在改的那一处之外压暗一层，眼睛直接落在要改的地方；标号是画面上的一枚实底小牌（亮青底、近黑字），不靠描边字压在活动的画面上，角上四粒方点看着 5px、能抓的有 12px。
  画面标记这一套颜色和强调青同色系、比 --teal 再稳一档：圈出来的那一块要压在活动的画面上，饱和度太高就成了一道会跳的霓虹；标记参考图上画的是同一套颜色。画面底边浮一条工具行，管的全是「手上这一下」：笔刷粗细、撤回上一步、清除全部 —— 它跟着手停在画面里，不和下面那一行「改整段还是改一段」混在一起。笔刷粗细归一化到画面宽度，所以同一档在任何分辨率的素材上涂出来一样粗；同一处续笔沿用它当初那一档，中途改滑杆不会把先前那几笔一起加粗。撤回是一条真正的栈：画面上按下去、轨道上拖一把、换一次作用范围，各算一步，误触的小框走的也是这条路；两者在没有可撤回的一步 / 没有标记时各自置灰并说出原因，画布那条 ⌘Z 仍在外面兜底。
- 「改整条 / 只改这一段」是一枚开关，不是两个并排的按钮 —— 只有开和关两个样子，并排两个按钮得先读完两条文字才知道现在是哪一档。当前范围写在同一行的末尾：开关说「改不改一段」，那个数说「改的是哪一段」——没开那一档时这里什么都不写，开关本身已经说了「改的是整条」，再补一句「整段 00:00–00:10」只是把同一件事说第二遍。轨道自己是一张卡片：上面一行把这一段读出来（起点 → 终点、多长），中间一把尺子，下面才是可拖的那条轨；选区之外的缩略图暗下去 —— 选了哪一段，不读数字也看得见，所以选区本身不填色，填了就把缩略图盖住了。两端的把手看上去是一粒 4px 的细条，能抓的却有 14px：细是给眼睛看的，宽是给手用的。
- 每标一处就自动截下那一帧（标记画在图上），作为**标记参考图**挂在源视频右边的参考素材栏里，一秒一张、同一秒的几处画在同一张上，和别的参考素材长得一样 —— 图上画着的框自己就说明了它是怎么来的，不再另加描边或时间角标。它完全由句子里还留着的标记决定：删掉一枚标签，右边那张图跟着消失。
- 更换源资产或其媒体文件静默清除标记：句子里的标签当场消失、入口旁的计数回到「未标记」，这本身就是反馈，不另弹横幅。
- 延长默认向后，向前 / 向后分别表示「新增 → 原视频」「原视频 → 新增」，提示词前缀常驻显示当前方向与新增时长。新增时长在参数浮层里设置，不以 30 秒减原片时长计算。
- 节点上那条延长轴只说一件事 ——「新增的是接在原片哪一头的哪一截」：两头都是定宽的小口，没选中的那头是虚线、只摆一枚朝外的角标和方向，选中的那头描实、底下补一行「+5s」。中间是原片摊成的一条胶片（几格缩略图各取自己那一段的中点，和时间轴上那十格同一份帧缓存），左端写着「原片」、右端挂着自己的时长。两头的宽度不跟着秒数走：轴上大半的地方留给那几格缩略图，那是这条轴上唯一有画面的东西，而「有多长」那一行字自己已经说清楚了 —— 否则一截 30 秒的新增能把 5 秒的原片挤成一条缝。秒数档也不摆在这条轴上，它是参数，归参数浮层那一栏。专注态那块屏上不再重复标时长：屏底下就是这段视频自己的轴，同一个数不写两遍。
- 视频时长要求按任务类型分，待编辑视频和辅助参考视频共用同一条：2.5 的编辑任务两者都是 4–30 秒（2.0 系列 2–30 秒），参考生成新视频与延长一律 2–30 秒。换过去会让手上的参考视频不合规的型号，在模型列表里就灰掉并说出区间。
- 视频输入时长按本次有效输入计算，每段视频都按整条原片计入合计。参考视频同样要能读出时长。
- 模型与参数为独立入口；模型清单与平台一致，不支持当前模式或会让标记失效的型号显示原因。参数浮层即时保存清晰度、时长、比例和声音，编辑时长随原片，Seedance 2.5 首尾帧比例随首帧，编辑与延长比例随原片；可灵与 Wan 没有声音开关。提交记录与界面显示的参数一致：不锁定比例的型号照手选值提交，没有声音开关的型号不夹带声音。换到不响应范围的型号时标记留着不被抹掉 —— 手画的东西比一个开关贵，那些型号在列表里本来就是灰的，真要放大范围由「移除标记，改整条」显式解除。
- 节点按类型从 1 开始编号：视频节点1、图片节点2、文本节点3。画布上的标题和它当素材时的名字一直是同一个，两处不分家；新建、粘贴取「现有最大号 + 1」，删掉中间一个再新建不会撞名。从「局部修改 / 延长视频」长出来的那个节点直接叫「局部修改视频：视频节点1」—— 两件事长出来的节点同名，它们是同一个功能的两条路，改的是画面里一块地方还是片尾接一段，由标题栏右边那枚「编辑中 / 延长中」徽章说。连着操作只把手数往下数：这个节点再点一次是「局部修改视频：视频节点1 · 2」，不写成「局部修改视频：局部修改视频：视频节点1」—— 念到第三层就读不下去了，这一条具体引用的是哪一段视频，连线和面板里的来源信息比名字说得准。名字被占了也接着往下数，同一段视频编辑两次不会长出两个同名节点。用户手动改过名字，从它派生出去的就以改后的名字为根、从第一手重新数（「局部修改视频：主角特写」），手打过名字的那个节点自己也不再被自动改口。节点 ID 仍是随机四字母，引用绑定的始终是它，和名字无关。
- 选中一个节点，上面那排入口和下面那块生成面板围着它站定：**面板永远贴在节点下沿，不会为了躲屏幕边而往上收**。以前它撞到屏幕底边就被往上挪，挪着挪着就盖住了节点自己 —— 而这块面板说的就是「这个节点要生成什么」，盖住它等于把话题本身挡了。放不下不该由面板让步，该由镜头让步：入口 + 节点 + 面板凑成一叠，哪头出了框就把这一叠挪回画面中间（320ms 的一下，不是瞬移）。整叠比视口还高时先保住面板完整露出来，上面那排入口该裁就裁 —— 入口是顺手的几件事，面板是这会儿真正要用的东西。面板的高度上限也为此让出 180px：顶到满屏就等于逼着镜头把节点推出画外。
- 镜头只在「刚选中 / 换了节点 / 切 Tab 让面板高矮变了」时动一次，之后就交回给用户：拖节点、拖画布、缩放时面板只是跟着走，画布不会一路追着抖。
- 画布保留节点拖动、连线、复制粘贴、撤销重做、文件上传和外部文件拖入。面板仍然可能盖住它下面那个节点 —— 盖住的地方点不着也拖不动，Esc 收起面板（取消选中）再拖；面板本身开着的时候，Esc 先关面板里的浮层。
- 连线可以就地断开：悬浮到线上，线本身亮起来并在中点亮出一把剪刀，点一下只断这一条连接，两头的节点和面板草稿都留着，⌘Z 接回来。剪刀平时不占位，只在悬浮时出现；素材退出「本次输入」由连接变化自己带出来（`syncConn`），走的是和拖连线同一条路。

## 演示范围

提示词不设门槛：一句话都不写也能生成 —— 空句子是用户的选择，不是缺一步没做完。生成按钮只有在「素材或参数真的不成立」时才灰（时长不合规、缺首帧、标记越界等）。价格与余额统一叫星钻，底栏是这一次要花多少（默认 5 秒 720p 是 188），顶栏是账户余额，同一枚星芒图标。视频生成按钮只创建、完成并记录演示任务：源视频、有效资产 ID、引用、标记组（逐处的归一化坐标、笔迹与秒数）、标记参考图截自第几秒、时间范围、方向、输出含义和参数快照都记在 `gen.tasks` 里，但面板上不摆任何任务小字 —— 走查时看的是界面本身，不是界面下面的一行回执（需要导出时再另开入口）。不调用真实模型，不扣费，不裁切编码，不生成或冒充 AI 编辑结果。

整段编辑目标为整条视频；延长目标为新增片段。本轮不自动拼回源视频，也不承诺逐帧精准修改。

状态保存在内存，刷新或切换示例场景会重置。图片与文本仍使用原有模拟生成功能。所有默认媒体位于 `public/media`，图片模拟生成仍使用在线图片。

## 验证重点

`src/store/generator.test.ts` 覆盖草稿恢复、换源、引用清理、模型兼容、任务快照，以及断线换源、模型来回切换这类连续操作。`src/generator/marks.test.ts` 覆盖标记本身的规则：误触的小框、画笔外接框与采点阈值、笔刷粗细的区间与滑杆换算、一组标记怎么读、作用范围怎么推出来、越界与失效的判断、时间段的取法。`src/store/versions.test.ts` 覆盖版本归属与三档分类：一个节点只收自己和直接派生出去的那一层，自己产出的都读作「生成」，原地再生成不改写先前那一版。`src/store/canvas.test.ts` 里另有一组覆盖操作节点的命名：连续操作只往下数手数、手动改过的名字当根、同名时接着数。画布撤销与真实媒体元数据测试继续保留。

主目录：`src/canvas`（画布）、`src/nodes`（节点与媒体）、`src/generator`（面板、节点上的标记编辑台、预览、参数与任务逻辑）、`src/store`（状态）、`src/demo`（本地样例）。
